# Обнаружение подозрительных входов по журналам аутентификации

Учебный проект по теме № 5. Детектор оценивает одно событие аутентификации по шести полям и выводит оценку риска, решение по порогу, пропуски и объяснение. Эксперимент полностью воспроизводится на синтетических данных.

## Запуск и демонстрация

Требуется Python 3.11–3.13. Релиз проверен на Python 3.13.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python auth_risk.py train
python auth_risk.py detect data/demo.csv
```

Для Windows PowerShell команда активации — `.venv\Scripts\Activate.ps1`. Команда `train` создаёт локальный файл модели. Используйте с `detect` только собственный файл модели, сформированный обучением.

Вход `detect` — CSV с заголовком и полями ниже. Пустая ячейка означает неизвестное значение. Дополнительные столбцы исключены из признаков. При наличии `event_id` дубликаты удаляются, при наличии `timestamp` события упорядочиваются по времени.

| Поле | Значения | Интерпретация |
|---|---|---|
| failures_15m | целое ≥ 0 | Неудачные попытки для учётной записи за 15 минут перед событием |
| new_device | yes / no | Устройство отсутствует в предыдущей истории |
| new_region | yes / no | Регион отсутствует в предыдущей истории |
| off_hours | yes / no | Событие вне обычного рабочего времени пользователя |
| client | browser / mobile / service | Тип клиента |
| mfa | passed / denied / unavailable | Результат многофакторной аутентификации |

Вывод — одна строка JSON на событие. `score` — некалиброванная оценка, `alert` — решение при зафиксированном пороге. `contrast` показывает изменение исходной оценки при замене одного поля типичным значением из обучения. Положительное число означает, что исходное значение повышало оценку относительно этого ориентира. Эффекты взаимозависимы и не складываются.

## Данные и оценка

В генераторе используются шесть перекрывающихся сценариев. Легитимные события включают обычные входы, поездки и работу службы поддержки. Подозрительные события включают серии ошибок, незнакомый контекст и малозаметные входы. Каждый сценарий задаёт распределения полей. Разметка известна из генератора. Реальные учётные записи и сетевые операции отсутствуют.

Генератор создаёт 21 720 строк, включая 120 повторов. После очистки остаётся 21 600 событий за 90 дней. Разбиение по UTC-дням в пропорции 60/20/20. Преобразователи обучаются на первых 54 днях. Порог и модель выбираются по F1 на следующих 18 днях. Последние 18 дней оставлены для оценки со сдвигом распределения.

| Модель | Порог | Accuracy | Precision | Recall | F1 | AP |
|---|---:|---:|---:|---:|---:|---:|
| Частый класс | 0,50 | 0,969 | 0,000 | 0,000 | 0,000 | 0,031 |
| Логистическая регрессия | 0,87 | 0,938 | 0,198 | 0,326 | 0,246 | 0,214 |
| Случайный лес | 0,77 | 0,923 | 0,167 | 0,370 | 0,230 | 0,186 |

При выбранном пороге логистическая регрессия выдала 222 сигнала. Из них 44 соответствуют подозрительным событиям, 178 оказались ложными. Модель пропустила 91 подозрительный вход. Результат поддерживает проверку в теневом режиме с аналитиком и контролем качества журналов. Для рабочего SOC потребуется независимая оценка на локальных данных.
